# Build API 500: Optional Upgrade Slots

## Symptoms

After successful authentication, `POST /api/builds` initially returned 500 with a
`NullPointerException`. The backend logged only the error type; the cause was narrowed
down using the stack trace from the container log.

## Causes

1. `BuildPayload.create()` stored eight optional upgrade fields using `List.copyOf(...)`.
   Empty slots are represented as `null` so their positions (`upgrade_1` through
   `upgrade_8`) are preserved. `List.copyOf` rejects `null`.
2. After a successful save, the same error occurred again in
   `BuildAssembler.storedPayload()` while rebuilding the response.

## Fix

Both locations now use an immutable, null-tolerant list. This preserves the positions
of empty upgrade slots while keeping the payload immutable.
