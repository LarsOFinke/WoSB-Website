# Build-API-500: optionale Upgrade-Slots

## Symptome

`POST /api/builds` lieferte nach erfolgreicher Authentifizierung zunächst 500
mit `NullPointerException`. Das Backend protokollierte nur den Fehlertyp; die
Ursache wurde mit dem Stacktrace aus dem Container-Log eingegrenzt.

## Ursachen

1. `BuildPayload.create()` legte acht optionale Upgrade-Felder mit
   `List.copyOf(...)` ab. Leere Slots werden als `null` geführt, damit ihre
   Position (`upgrade_1` bis `upgrade_8`) erhalten bleibt. `List.copyOf` lehnt
   `null` ab.
2. Nach erfolgreichem Speichern trat derselbe Fehler in
   `BuildAssembler.storedPayload()` beim Wiederaufbau der Antwort erneut auf.

## Behebung

Beide Stellen verwenden jetzt eine unveränderbare, null-tolerante Liste. Die
Positionen leerer Upgrade-Slots bleiben damit erhalten, während der Payload
weiterhin nicht mutiert werden kann.

## Diagnosebefehl

```bash
sudo docker compose --env-file /opt/rbf/shared/.env \
  -f /opt/rbf/current/infrastructure/compose.release.yml \
  logs --since=10m api \
  | grep -A35 -B3 'api_error status=500 method=POST path=/api/builds'
```
